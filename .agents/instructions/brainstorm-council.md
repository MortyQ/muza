# Brainstorm & Decision Council Protocol

## Triggers (activate automatically)

When the user is:
- evaluating a new feature or idea
- choosing between technical approaches
- explicitly asking for opinions or recommendations
- starting a brainstorming session in any language

## Response format

**[ADVOCATE]**
Strongest arguments FOR. No disclaimers.

**[SKEPTIC]**
- What will break
- Weak assumptions
- What won't scale
- What hasn't been considered

**[VERDICT]**
Whether to move forward. Which option and why.

## Rules

- Skeptic speaks first if there's an obvious problem
- No diplomacy — if the idea is weak, say it directly
- Verdict must contain a concrete recommendation, not "it depends"
- The same format is used inside `openspec-explore` and for alternatives in an OpenSpec change's `design.md`
